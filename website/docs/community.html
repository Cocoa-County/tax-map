Create a map / Build with an AI agent

For project creators / No coding needed

Set up once.
Create projects with your agent.

Install and sign into one AI CLI, then set up and activate taxmap once. Ask for an app for your city and state: the agent handles routine settings and research, you approve exact content and review a local preview. A manual walkthrough remains available.

This guide is for creating a new project. To explore an existing map, read the separate app user guide.

A CLI is an application you launch by typing its name in a terminal. You do not need to write code, prepare spreadsheets, install taxmap yourself, or configure GIS manually. You do need to sign in, review permission requests, and check the result.

Tools ready, then app generation. The agent verifies that the plugin's skills and MCP tools are live. Continue in the same session when supported; current Codex requires a new session after installation. A full CLI restart is not a universal requirement. The agent may need permissions or help with essential missing records. Your first result stays local; nothing is published automatically.

1. What you need

  • A Windows, macOS, or Linux computer supported by your chosen agent, with an internet connection and space for documents and parcel data.
  • One agent CLI: Codex, Claude Code, or GitHub Copilot CLI. You do not need all three.
  • An account with access to that agent. Subscription limits, API billing, and organization policies vary. Check the provider's current requirements before installing.
  • A city and state. A public question or focus, fiscal year, folder and starting documents are optional.

The agent needs permission to write within your chosen workspace, install project dependencies, and access public sources. It also needs web research and PDF/image-reading capabilities; taxmap's MCP supplies document and GIS operations, not a web search engine or an AI model. If those capabilities are unavailable, the agent must explain the blocker rather than pretend it researched the city.

You do not need a GitHub repository to build a local preview. GitHub authentication and Pages setup come later if you decide to publish.

2. Install one agent, launch it, and sign in

A terminal is a window where you type commands. On Windows, open PowerShell or Windows Terminal; on macOS, search for Terminal with Spotlight; on Linux, open your desktop's Terminal. You do not need to create a project directory or install taxmap first.

Use the official installation guide for your operating system. Close and reopen the terminal if the agent command is not recognized, then launch it with the command below and sign in. Start from a safe folder where you are comfortable granting access, not a folder full of unrelated private documents.

3. Paste this short tools-setup request

Paste this into your signed-in agent, not the terminal's command prompt. You can use it unchanged:

Help me set up taxmap for this CLI. Ask before downloading, installing software, or changing my configuration. Confirm a stable, separate local tools folder, then download https://github.com/Cocoa-County/tax-map there and follow SETUP.md at the repository root. Install one taxmap plugin containing all its skills and MCP connection; do not register a separate MCP server or loose skills. Preserve existing settings and save the setup handoff. Do not create a project yet. Activate the plugin using this client's supported method and verify live skills and MCP tools. Save any required session steps and tell me how to ask for an app for my city and state.

The repository's SETUP.md carries the technical instructions. The agent should confirm a tools-download location, install requirements, and install one taxmap plugin containing all its skills and MCP connection for your chosen CLI. Persistent registration keeps the bundle available in later sessions, outside the downloaded repository.

4. Approve setup and verify activation

The agent should do the installation and configuration work, but it cannot approve its own permissions, sign in for you, or bypass your organization's policies. Review requests to install software, download records, or write files. Ask it to explain anything unexpected. Keep API keys and passwords out of the conversation.

Skills teach the agent the workflow; MCP connects it to taxmap's local tools. One plugin groups them so you can enable or disable taxmap together. The agent should preserve existing settings, check its changes, and save a TAXMAP-SETUP.md handoff in the tools folder. Saving configuration alone does not prove a live connection.

Activate, then verify. Current Copilot can refresh in-session; Claude can use /reload-plugins; current Codex requires a new session after plugin installation. Follow your installed version's supported method and review trust, reload or MCP approval prompts. Ask for the handoff path and any exact remaining steps. No city project should have been created by the tools-only request above.

There is no mandatory restart when the required skills and MCP tools are already live and no client-required session step remains. A standalone test process does not prove that the running agent has loaded them. Older clients or failed activation may need a new session or restart. See the client-specific references in SETUP.md. If setup is blocked, keep the error and saved handoff rather than turning off protections. If your original request already asked for an app, the agent can continue once ready without another build request.

5. Request an app in one sentence

The agent first checks the shared jurisdiction resource catalog for reusable city/county websites, meeting portals, GIS services and tax-bill templates, then verifies them for your project. Specific documents and evidence stay in your project. Missing catalog entries do not stop official-source research.

Once the plugin's skills and tools are live, say:

Build a taxmap app for Martinez, CA.

Replace the city and state with yours. The agent verifies its live tools, derives a project name and title, and uses ~/taxmap-projects/<city-id>. It continues through official-source research and modeling without a separate build request or optional-settings questionnaire. Include a fiscal year, folder, focus or starting records if you want; otherwise it verifies the latest adopted year. An explicit year must never be silently replaced.

The agent resumes a clearly matching project and preserves existing work. It asks only about genuine ambiguity, permissions or essential blockers, including conflicting folders. If you prefer to choose settings one at a time, say Create a new taxmap project. Walk me through the setup.

You can also use individual skills, edit project files or follow the manual CLI workflow. The one-request flow is optional; manual work retains the same evidence and privacy requirements and does not require a second MCP registration.

If the tools are still missing after the supported activation steps, give the agent the saved TAXMAP-SETUP.md path and ask it to diagnose registration. Do not accept a claim that setup worked without available tools.

New projects include a personalized PROJECT-PROMPT.md; guided builds also keep progress and approval in app.yaml. You do not need to assemble a long prompt or repeat the chat later. Starting resources are unverified references, not permission to upload documents. Publication still requires separate approval.

6. Open and review the local preview

Approve one consolidated content review first. The agent should show the exact parcel fields, extra roll columns, resource IDs/titles/origins, citations, document-copy policy, public explanations and material model prose. Local previews use the same content controls as a public site: resource metadata, citations and files are withheld until you approve the specific resources. If you decline a subset, the agent must remove it and explain missing citations, not expose it through notes. Unchanged content can resume without another content questionnaire; changed content needs review. Host permission prompts remain separate. Approving content does not authorize a commit, upload or public deployment; that needs separate permission. Check redistribution rights before including document copies.

The agent should give you a browser address such as http://127.0.0.1:8000/, using the actual port it started and checked. Open that address in your browser on the same computer. It is not a public link; other people cannot use it to view your app.

Expect a map with parcel search, district information, source links, and calculators where supported by the evidence. Useful partial results are labeled clearly, with a coverage page showing missing assessments, source-total differences and formula limitations. Source amounts stay unchanged. File integrity is not the same as financial reconciliation, and an absent charge is not zero. No supported usable model means an honest blocker, not a mock app.

Where verified and approved, official bill links open the county's site for the selected parcel; the county controls availability and bill year. The agent should explain missing or omitted bill links, not silently skip them because the app models only part of a bill. Links do not initiate payments or copy bills into the app.

Use the review checklist. Check the fiscal year, a few known parcels, official amounts versus estimates, citations, and coverage gaps. If research could not be completed, ask the agent to show its saved inventory and blockers rather than assume an absent charge means zero.

7. Reopen, update, or publish later

The agent should leave the preview running for your review, not stop it just because the build is complete. Ask it to stop after you finish reviewing or when you want to close it. The project files stay on your computer after the preview stops. A preview started through MCP can stop when the agent or its MCP process exits; a sleeping computer also makes it unavailable. Ask the agent to explain its server's lifetime and shutdown method.

To reopen it, start your chosen CLI and ask it to resume the taxmap app at the saved project path. It reads current files and app.yaml, checks approval and starts a verified preview on an available localhost port. The handoff also includes a standalone restart command; Ctrl+C stops that server. The recorded old URL does not prove a server is still running. You do not have to repeat completed extraction just because a chat ended.

If a dependency installation, login, portal, or research tool fails, preserve the exact error and ask the agent to diagnose it. A work or school device may require an administrator's help. Do not turn off security protections to get past an unexplained failure.

Publish only after review

When you are ready to publish, explicitly approve the scope, public fields and individual resources. Resources stay private by default, even when cited; the agent must record approved resource IDs before their metadata, citations or files appear publicly. Exclude owner names, mailing addresses, private correspondence, and other unnecessary personal data. Review extra roll columns and public model notes too. Check redistribution rights before copying documents into the public site. Revoking approval requires rebuilding and redeploying to remove previously published content. GitHub Pages requires a GitHub account, a suitable repository, authentication, and Pages configuration. Have the agent explain visibility and any automatic redeployment triggers before creating or pushing anything. Follow the publishing guide; GitHub Pages hosts the finished static app, not the research agent.

Guided previews use a checked export under .taxmap/app-previews, not the manual default site/. Publish only the approved export, including its coverage page, never the whole cache. A generic rebuild does not automatically carry over guided approval or disclosures.

No sources are guaranteed to be complete, and no calendar-year update is automatic. New adopted records require another research and review pass. Broader civic apps would require additional development.

What to check before publishing →

Enable, disable, or remove taxmap tools

Your CLI's plugin manager controls the taxmap bundle. Disable temporarily stops loading its skills and MCP; enable restores them; uninstall disconnects the bundle from that CLI. For local marketplaces, uninstall may leave a disabled catalog entry and files on disk; the agent should explain what remains. These actions keep your city projects, documents, maps, and separate tools environment.

Disable the taxmap plugin, keeping my projects and data.

Ask the agent to use its taxmap-uninstall skill for guided removal. It should identify the installation, explain the exact changes, ask for approval, apply the client's supported refresh/session step and verify the live result. Restart only when needed. If taxmap is already disabled, its skill is unavailable: ask the agent to follow UNINSTALL.md in the saved tools checkout instead, using the setup handoff path.

Removing the separate tools environment is optional and requires another confirmation. Old loose skill copies or separately registered MCP servers must be checked too; removing the plugin alone does not remove them. Shared Python, your AI CLI, credentials, and published sites are left alone.

Review your project before publishing

Found a reusable portal, GIS service or bill template worth sharing? Ask the agent to use contribute-jurisdiction-resources. It reviews the exact public metadata with you and uses your authorized GitHub tools to open a fork-based pull request to taxmap-resources. Maintainers approve and merge. No specific documents, individual bills or private project files belong there, and preview approval is not permission to submit a contribution.

  • Are the sources final or adopted, and do they cover the intended year?
  • Do the roll's row count and total agree with the document?
  • Did the parcel identifiers match? Are duplicates or unmatched records explained?
  • Do the calculations agree with the roll? If not, is the reason stated rather than concealed?
  • Are bill codes verified from official records, not guessed from an abbreviation?
  • Are missing inputs and approximate boundaries clearly labeled?

Ask for a validation summary, not just a polished screenshot. In Concord, some formulas reproduce the roll while others depend on missing or proxy inputs; that distinction matters.

Optional alternative: use a direct project installer instead

Install and create your project with one command

This is an alternative, not a prerequisite for the agent-led workflow above. Run from any folder; it asks for your project name and location, creates the directory and missing parent folders, and installs all runtime requirements. No Git clone or administrator terminal is required. It does not install your agent or register persistent skills/MCP.

Windows PowerShell

$p = Join-Path $env:TEMP ("taxmap-" + [guid]::NewGuid() + ".ps1"); try { Invoke-WebRequest -UseBasicParsing https://raw.githubusercontent.com/Cocoa-County/tax-map/main/scripts/install.ps1 -OutFile $p -ErrorAction Stop; & $p } finally { if (Test-Path -LiteralPath $p) { Remove-Item -LiteralPath $p } }

macOS/Linux Bash

( f="$(mktemp)" || exit; trap 'rm -f "$f"' EXIT; curl -fsSL https://raw.githubusercontent.com/Cocoa-County/tax-map/main/scripts/install.sh -o "$f" && bash "$f" )

Answer prompts for project name, exact location, and jurisdiction, then optional title, county, state, fiscal year, research focus, and starting paths/URLs. Enter your requested fiscal year as the research target; leave it blank only if you have no preference. The agent will verify adopted records before modeling that year. References are not opened, uploaded, or fetched. Review and confirm; existing non-empty destinations are refused.

If Python is missing, setup asks permission to install user-scoped uv and managed Python. It does not change system Python, shell profiles, or execution policy. Downloads need GitHub, PyPI, and (for Python bootstrap) Astral. Review the PowerShell launcher, Bash launcher, and shared wizard before trusting them; they download matching source and may execute Astral's installer. Follow organization policies rather than bypassing restrictions.

Keep the generated .venv and .taxmap-tools folders in place. taxmap-install.json records paths and revision; PROJECT-PROMPT.md is your editable local research request, not a published page. Nothing is researched or published during installation.

Your project is already created; do not initialize it again. Ask your agent to follow SETUP.md's plugin steps using the recorded tools paths and existing environment, preserving settings. Activate and verify the live tools, using a new session/restart only when required, then open the existing project and say: Read PROJECT-PROMPT.md in this project and follow it. Older projects may lack this file; ask the agent to inspect saved files instead of reinitializing.

Failures stop explicitly. Inspect any partial project and retry in a new empty folder. Cancelling can leave managed Python installed; do not remove it while an environment depends on it. For pinned downloads, replace main with a full commit SHA and set TAXMAP_REF to the same SHA. See the README installer details.
