Create a map / Developer guide

For project creators / Python and CLI

Build a reproducible city project.

Python tools and plain project files power the research workflow. A static Leaflet application delivers the public result.

Install and create a project

For agent-led setup, start with the two-stage CLI guide: ask your chosen CLI to download taxmap and follow SETUP.md, restart after tools registration, then ask it to create a project. The one-command interactive installer is an optional alternative for Windows PowerShell or macOS/Linux Bash. It prompts for name, custom destination, and jurisdiction, offers optional project settings, bootstraps Python with permission if needed, and installs every runtime dependency in the project's .venv. It refuses non-empty destinations, records its source revision in taxmap-install.json, and prints exact CLI/MCP commands. AI-agent installation and MCP registration remain separate.

For repository development, the manual workflow below requires Python 3.10 or newer and Git. Node.js is needed for JavaScript parity tests, not to serve the generated map. These commands use Windows PowerShell from the repository root:

git clone https://github.com/Cocoa-County/tax-map.git
cd tax-map
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev]"
.\.venv\Scripts\taxmap init projects\martinez --name martinez `
  --jurisdiction "City of Martinez" --county "Contra Costa" `
  --state CA --fiscal-year "2026-27"
.\.venv\Scripts\taxmap --project projects\martinez validate

On macOS/Linux, use .venv/bin/pip and .venv/bin/taxmap, and use shell-appropriate paths and line continuation. The Martinez command only initializes an empty project; it does not research or populate city data.

The example fiscal year must be changed to the year supported by your sources. Use taxmap <command> --help for command options. Prefer an explicit --project to avoid editing another project by accident.

Generated agent request

Every new project created through the CLI, MCP, or installer includes PROJECT-PROMPT.md. Initialization renders a packaged template with the project root, settings, fiscal-year instructions, and optional research context. It is local project content, not a published site note or automatic client configuration.

Use init --focus "Explain downtown assessments" and repeat --starting-resource PATH-OR-URL for optional references; MCP project_init accepts focus and a starting_resources list. References are not fetched or ingested by initialization. Ask an agent to read the generated file; edit it directly if needed. Later configuration changes do not overwrite your request. Existing projects are not migrated; do not reinitialize them to generate a request.

Multi-skill plugin and lifecycle

The repository's portable plugin manifest shares all skill content. build_plugin.py creates a new local marketplace with portable Copilot/Codex packaging, a Claude adapter, and machine-specific projectless MCP. Supply --output, --mcp, and --revision using the installed environment's Python. Existing destinations are refused; inside the checkout use .taxmap-plugins/. The builder does not register configuration or create a city project.

Follow SETUP.md for native client installation and restart. Do not separately copy skills or register MCP: independent copies bypass the bundle toggle. Use the plugin manager for enable/disable/uninstall, and taxmap-uninstall or UNINSTALL.md for ownership checks, legacy cleanup, and optional environment removal. City projects and shared runtimes remain intact. Updates require a new build and approved refresh/reinstall.

Project files are the source of truth

taxmap.yaml                 jurisdiction, APN rules, layers, site
resources.yaml              source registry and original URLs
resources/                  ingested files
model/sources.csv           research inventory and findings
model/districts/*.yaml       membership, zones, bill labels, evidence
model/rolls/*.csv|yaml        per-parcel amounts and roll metadata
model/formulas/*.yaml        inputs, constants, lookups, expressions
model/notes/*.md             published explainers
gis/                        feature layers and district outlines
derived/                    rebuildable extractions
.taxmap/                    rebuildable search/provenance cache
site/                       generated public map

Configure taxmap.yaml and model files directly, or use MCP tools. Schemas reject unknown fields. See the typed models for the authoritative field reference and the Concord model for complete examples.

Configure publication explicitly

site:
  title: Martinez Assessment Map
  subtitle: Public records, explained
  publish_fields:
    - APN
    - ADDRESS
  disclaimer: Unofficial map. The adopted roll and county bill are authoritative.

Replace APN and ADDRESS with verified layer fields. Include fields needed for calculator prefilling without publishing unnecessary personal data. Nested configuration objects are replaced as a whole by MCP project_configure; preserve existing settings when updating them.

Evidence and formulas

Evidence has resource, optional 1-based PDF page, locator, quote, and note. Put printed page numbers in the locator. Formula expressions use a parsed language, not Python or JavaScript code; Python and browser evaluators must stay equivalent.

District bill_labels hold exact code/description pairs with a verification year and evidence. site.parcel_links supports URL-encoded {apn} and {apn_display} templates with fixed HTTP(S) hosts. Verify endpoints and fiscal-year behavior before configuring links.

Acquire, model, validate, build

These commands illustrate the sequence. Replace file paths, resource IDs, and the layer URL with verified inputs. Create the referenced district/formula definitions before final validation.

taxmap --project projects\martinez add C:\records\report.pdf --title "Adopted report"
taxmap --project projects\martinez extract RESOURCE_ID
taxmap --project projects\martinez search "assessment roll"
taxmap --project projects\martinez gis describe VERIFIED_LAYER_URL
taxmap --project projects\martinez gis download parcels --url VERIFIED_LAYER_URL --kind parcels
taxmap --project projects\martinez roll import district-2026-27 C:\records\roll.csv --district district
taxmap --project projects\martinez roll summary district-2026-27
taxmap --project projects\martinez roll join district-2026-27
taxmap --project projects\martinez check FORMULA_ID
taxmap --project projects\martinez outlines
taxmap --project projects\martinez validate
taxmap --project projects\martinez build
taxmap --project projects\martinez serve --port 8000

For these shorter commands, activate the virtual environment or replace taxmap with its executable path. Open http://localhost:8000/; file:// cannot load the map data correctly.

ArcGIS downloads are resumable and rate-limited. For a local WGS84 GeoJSON layer, use gis import. Verify APN normalization, address fields, coverage, and calculator inputs. Supply stated totals/counts when importing rolls, then inspect summary checks and parcel joins.

Never tune a constant merely to force a match. Keep adopted roll values authoritative and explain formula mismatches, proxy inputs, and missing data.

Connect an AI agent

Run the installed stdio server with an explicit project:

.\.venv\Scripts\taxmap-mcp --project projects\martinez

In your MCP client's configuration, set the command to the virtual environment's taxmap-mcp executable and pass --project plus the project path as arguments. TAXMAP_PROJECT is an alternative. The agent can also call project_open or project_init.

The repository's VS Code configuration initially points to Concord. Change it for a different project. Provide the agent playbook, agent guide, and skills through your client's supported context/skill mechanism. A folder's presence alone does not guarantee automatic skill discovery.

Develop and test

The CLI and MCP server call shared modules under src/taxmap: project storage, ingestion, extraction, indexing, GIS, assessments, formulas, and site generation. The server performs deterministic operations; interpretation belongs to the agent.

.\.venv\Scripts\python -m pytest -q

Tests cover models, integrations, MCP, geometry, rendering, and formula parity. Install Node.js to run the parity cases. Concord parcel-dependent tests run when its downloaded layer exists; tests that do not need geometry still validate its committed models.

For frontend changes, check desktop/mobile layouts, keyboard access, search, overlap selection, calculator updates, citations, and deployment under a repository path such as /tax-map/concord/. Keep both formula implementations aligned and add parity cases for semantic changes.

Publish with GitHub Pages

This repository's Pages workflow installs taxmap, downloads Concord parcels, validates its model, builds its map, and combines it with the landing page and documentation. Pushes to main or manual workflow dispatch deploy the result.

For a standalone city project repository, copy the workflow template into .github/workflows/pages.yml. It assumes taxmap.yaml is at the repository root and a configured parcel layer is named parcels. Adjust paths or download steps if your project differs.

  1. Commit project configuration, approved sources, models, and required GIS definitions. Avoid committing large parcel downloads or generated caches.
  2. Check that the GitHub plan and repository visibility support Pages.
  3. Choose GitHub Actions in repository Settings > Pages.
  4. Run the workflow and inspect validation/build warnings and deployment status.
  5. Verify the actual public URL, a parcel deep link, calculator, and source links.

Keep links relative for repository-prefix hosting. Failed downloads or validation must stop deployment, rather than publishing an incomplete replacement. A manual rebuild does not automatically refresh adopted reports or review annual model changes.

Troubleshooting

  • No project open: pass --project or call project_open; confirm the folder contains taxmap.yaml.
  • Unmatched roll APNs: inspect normalization and coverage; check retired parcels and duplicates rather than discarding records silently.
  • Calculator cannot prefill: verify source fields and publication allow-list; read build warnings. Missing data is not zero unless the documented method says so.
  • Unreadable PDF: inspect rendered pages or obtain a better source. Text extraction failure does not prove a fact is absent.
  • Blank map: serve over HTTP and check data requests, paths, and console errors.
  • Pages unavailable: check permissions, repository visibility/plan, Pages source, and Actions logs.

See the repository for CLI help, issue reporting, and the latest schemas.
