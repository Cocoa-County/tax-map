Create a map / Developer guide

For project creators / Python and CLI

Build a reproducible city project.

Python tools and plain project files power the research workflow. A static Leaflet application delivers the public result.

Install and create a project

For agent-led setup, start with the CLI setup guide: follow SETUP.md for tools installation, client-supported activation and live readiness checks, then say Build a taxmap app for Martinez, CA. using your city/state. Continue in-session when supported; current Codex requires a new session after installation. The agent continues through research, exact content review and a local preview. A setup-only walkthrough and the manual commands below remain available.

The one-command interactive installer is a separate optional alternative for Windows PowerShell or macOS/Linux Bash. It prompts for name, destination, jurisdiction and optional settings; bootstraps Python with permission if needed; and installs runtime dependencies in the project's .venv. It refuses non-empty destinations, records its source revision in taxmap-install.json, and prints an existing-project plugin activation/resume handoff. Reuse its checkout/environment and resume that project once live tools are ready; do not initialize another one. Agent sign-in and plugin registration remain separate.

For repository development, the manual workflow below requires Python 3.10 or newer and Git. Node.js is needed for JavaScript parity tests, not to serve the generated map. These commands use Windows PowerShell from the repository root:

git clone https://github.com/Cocoa-County/tax-map.git
cd tax-map
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev]"
.\.venv\Scripts\taxmap init projects\martinez --name martinez `
  --jurisdiction "City of Martinez" --county "Contra Costa" `
  --state CA --fiscal-year "2026-27"
.\.venv\Scripts\taxmap --project projects\martinez validate

On macOS/Linux, use .venv/bin/pip and .venv/bin/taxmap, and use shell-appropriate paths and line continuation. The Martinez command only initializes an empty project; it does not research or populate city data.

The example fiscal year must be changed to the year supported by your sources. Use taxmap <command> --help for command options. Prefer an explicit --project to avoid editing another project by accident.

Choose one-request generation or manual work

build-taxmap-app is an optional agent skill, not an embedded AI backend or a new autonomous CLI command. It derives ordinary settings, uses ~/taxmap-projects/<city-id>, preserves a requested year, and otherwise verifies the latest adopted year. It resumes matching projects and asks only about genuine ambiguity, permissions or essential blockers. Host permission prompts remain independent.

MCP toolResponsibility
app_startSafe defaults, create/resume, explicit year and path preservation.
app_statusDurable scope, adoption evidence, gaps and artifact references.
app_checkIntegrity plus roll totals/counts, joins and every formula/roll comparison.
app_reviewUnserved private export review; record the digest only after explicit user approval.
app_previewApproved export, available localhost port, owned server, HTTP health check and restart instructions.

Review exact fields, resource IDs, roll columns, document-copy policy, public notes and material model prose together. Changed export content needs review again; unchanged content can resume without another questionnaire. ready_with_caveats preserves supported partial scope and printed discrepancies. Structural errors, unparsed amounts, ambiguous joins and unsupported empty models block guided previews. Integrity success alone is not financial reconciliation.

For more control, ask Create a new taxmap project. Walk me through the setup., use individual skills/tools, or edit project files and run CLI commands directly without AI. Low-level commands remain compatible but do not enforce the guided approval lifecycle; the same evidence and privacy requirements still apply. Manual work does not require registering a second MCP connection.

Shared resources and pull-request contributions

taxmap-resources is a separate public catalog of reusable official jurisdiction entry points. YAML files record city/county websites, agenda/minute portals, parcel/assessment/boundary GIS services and bill templates with authority, dated verification, APN requirements and year caveats. Specific reports, meetings, individual bills and downloaded data stay in project evidence.

find-jurisdiction-resources reads a consistent catalog revision, matches the jurisdiction and its parent county, and rechecks official candidates. Metadata is a lead, not adoption evidence or publication permission. Catalog failures are recorded without blocking ordinary discovery. Before preview, account for verified site.parcel_links or an explicit omission reason; verify parcel identity, formatting and county bill-year behavior and include exact links in content review.

contribute-jurisdiction-resources prepares eligible additions/corrections as a standard part of the one-request build, without a separate request. Alongside the consolidated preview review, show the exact metadata/diff and public destination, explain that sharing helps make taxmap more powerful for the whole community, and ask a separate explicit sharing choice with no preselected consent. Skip the prompt when nothing eligible changed. Preview approval is never sharing permission; declining never blocks the app. Save the proposal/decision privately in derived/catalog-contribution.json, reference it through app_status, respect declined/deferred choices on resume and check existing PRs before creating duplicates. Material proposal changes require fresh approval.

After explicit sharing approval, deliver the preview then use the host's authorized GitHub tools to commit/push the approved minimal change on a contributor fork and open a PR to catalog main without another generic continuation question. Follow the catalog's schema, validator, tests and contributor guide. Maintainers approve and merge; never self-approve, auto-merge or push contributions directly to main. No credentials are stored in taxmap and no new MCP connection is required. If auth/tools or checks fail, preserve the blocker and provide a patch/manual PR handoff rather than claiming submission. Submission failures never block the app; installation/login requires separate permission. Standalone contributions remain supported.

Generated agent request

Every new project created through the CLI, MCP, or installer includes PROJECT-PROMPT.md. Initialization renders a packaged template with the project root, settings, fiscal-year instructions, and optional research context. It is local project content, not a published site note or automatic client configuration.

Use init --focus "Explain downtown assessments" and repeat --starting-resource PATH-OR-URL for optional references; MCP project_init accepts focus and a starting_resources list. References are not fetched or ingested by initialization. A build-intent agent reads it and continues automatically; setup-only users choose when to begin research. Later configuration changes do not overwrite your request. Guided resumes use current config and app.yaml without rewriting it. Existing projects are not migrated; do not reinitialize them to generate a request.

Multi-skill plugin and lifecycle

The repository's portable plugin manifest shares all skill content. build_plugin.py creates a new local marketplace with portable Copilot/Codex packaging, a Claude adapter, and machine-specific projectless MCP. Supply --output, --mcp, and --revision using the installed environment's Python. Existing destinations are refused; inside the checkout use .taxmap-plugins/. The builder does not register configuration or create a city project.

Follow SETUP.md for native client installation, activation and live verification. Do not separately copy skills or register MCP: independent copies bypass the bundle toggle. Use the plugin manager for enable/disable/uninstall, and taxmap-uninstall or UNINSTALL.md for ownership checks, legacy cleanup, and optional environment removal. Apply supported refresh/session steps and verify the live result; restart only when needed. City projects and shared runtimes remain intact. Updates require a new build and approved refresh/reinstall.

Project files are the source of truth

taxmap.yaml                 jurisdiction, APN rules, layers, site
app.yaml                    guided intent, progress, approval, last handoff (optional)
resources.yaml              source registry and original URLs
resources/                  ingested files
model/sources.csv           research inventory and findings
model/districts/*.yaml       membership, zones, bill labels, evidence
model/rolls/*.csv|yaml        per-parcel amounts and roll metadata
model/formulas/*.yaml        inputs, constants, lookups, expressions
model/notes/*.md             published explainers
gis/                        feature layers and district outlines
derived/                    rebuildable extractions and guided review/check reports
.taxmap/                    rebuildable caches; guided exports in app-previews/
site/                       low-level generated map (default)

app_preview returns the exact guided export path under .taxmap/app-previews. It leaves its loopback server running for review; stop with app_preview(stop=true). MCP shutdown stops it too. app.yaml stores the last URL and standalone restart command, not proof that a server is still running. Resume from current files and regenerate missing caches.

Configure taxmap.yaml and model files directly, or use MCP tools. Schemas reject unknown fields. See the typed models for the authoritative field reference and the Concord model for complete examples.

Configure publication explicitly

site:
  title: Martinez Assessment Map
  subtitle: Public records, explained
  publish_fields:
    - APN
    - ADDRESS
  publish_resources:
    - adopted-report
  publish_roll_fields: {}
  copy_documents: false
  disclaimer: Unofficial map. The adopted roll and county bill are authoritative.

Replace APN and ADDRESS with verified layer fields and adopted-report with an explicitly approved resource ID. The parcel allow-list is strict: excluded fields are not added back for calculators, search or labels, and hide_fields takes precedence. APNs are required for the public map; excluding them fails the build. Excluded addresses are omitted from search too.

Guided apps require an explicit parcel-field list. Low-level builds retain the legacy null = all fields behavior; do not rely on that for privacy. Obtain content approval before serving a local preview as well as before public deployment. Preparing an unserved private review export is not permission to serve it.

publish_resources defaults to an empty list, including in existing projects. Only approved resources' metadata, citation text and linked research inventory rows are exported. Ingesting or citing is not approval; URL-only inventory rows must first link to an approved resource. copy_documents copies only approved resources after rights/privacy review. Rebuilding removes prior generated copies when approval is revoked or copying is disabled; redeploy to remove previously published content.

Only assessment amounts and APN joins are public from rolls by default. Approve extra columns, including calculator inputs, with publish_roll_fields: {ROLL_ID: [COLUMN]}. Review model prose, roll notes and published explainers separately. Inspect build warnings for withheld citations and missing prefills. Nested configuration objects are replaced as a whole by MCP project_configure; preserve existing settings when updating them.

Evidence and formulas

Evidence has resource, optional 1-based PDF page, locator, quote, and note. Put printed page numbers in the locator. Formula expressions use a parsed language, not Python or JavaScript code; Python and browser evaluators must stay equivalent.

District bill_labels hold exact code/description pairs with a verification year and evidence. site.parcel_links supports URL-encoded {apn} and {apn_display} templates with fixed HTTP(S) hosts. Verify endpoints and fiscal-year behavior before configuring links.

Acquire, model, validate, build

These manual commands illustrate the sequence; no AI agent is required. Replace file paths, resource IDs, and the layer URL with verified inputs. Create the referenced district/formula definitions before final validation. Review exact export content before building or serving, and check totals/joins/formulas separately from validate. The commands do not enforce app.yaml approval or generate the guided coverage page.

taxmap --project projects\martinez add C:\records\report.pdf --title "Adopted report"
taxmap --project projects\martinez extract RESOURCE_ID
taxmap --project projects\martinez search "assessment roll"
taxmap --project projects\martinez gis describe VERIFIED_LAYER_URL
taxmap --project projects\martinez gis download parcels --url VERIFIED_LAYER_URL --kind parcels
taxmap --project projects\martinez roll import district-2026-27 C:\records\roll.csv --district district
taxmap --project projects\martinez roll summary district-2026-27
taxmap --project projects\martinez roll join district-2026-27
taxmap --project projects\martinez check FORMULA_ID
taxmap --project projects\martinez outlines
taxmap --project projects\martinez validate
taxmap --project projects\martinez build
taxmap --project projects\martinez serve --port 8000

For these shorter commands, activate the virtual environment or replace taxmap with its executable path. Open http://localhost:8000/; file:// cannot load the map data correctly.

ArcGIS downloads are resumable and rate-limited. For a local WGS84 GeoJSON layer, use gis import. Verify APN normalization, address fields, coverage, and calculator inputs. Supply stated totals/counts when importing rolls, then inspect summary checks and parcel joins.

Never tune a constant merely to force a match. Keep adopted roll values authoritative and explain formula mismatches, proxy inputs, and missing data.

Connect an AI agent

Recommended: plugin-managed connection

Follow SETUP.md, install and activate the single skills/MCP plugin, and verify live readiness. Current Copilot can refresh in-session; Claude can use /reload-plugins; current Codex requires a new session after installation. Use build-taxmap-app and app_start for one-request generation, or individual tools such as project_open and project_init for manual work. The server starts without a pinned project. Do not also register independent MCP or loose skills. Source edits do not refresh an installed bundle: updates need an approved runtime update when non-editable, a new bundle, client refresh/reinstallation, MCP reconnection for runtime changes, and live verification.

Manual alternative: independently managed MCP

For development or clients without plugin support, explicitly choose a separate stdio connection. Plugin disable/uninstall does not control this server or independently installed skills. Avoid running both setups for the same work; inspect legacy entries using UNINSTALL.md before migrating. For this manual alternative, launch the installed server with an explicit project:

.\.venv\Scripts\taxmap-mcp --project projects\martinez

In your MCP client's configuration, set the command to the virtual environment's taxmap-mcp executable and pass --project plus the project path as arguments. TAXMAP_PROJECT is an alternative. The agent can also call project_open or project_init.

The repository's VS Code configuration is a Windows-specific, Concord-pinned development example, not the plugin bootstrap. Change it for a different manual project. Provide the agent playbook, agent guide, and skills through your client's supported context/skill mechanism. A folder's presence alone does not guarantee automatic skill discovery.

Develop and test

The CLI and MCP server call shared modules under src/taxmap: project storage, ingestion, extraction, indexing, GIS, assessments, formulas, and site generation. The server performs deterministic operations; interpretation belongs to the agent.

.\.venv\Scripts\python -m pytest -q

Tests cover models, integrations, MCP, geometry, rendering, and formula parity. Install Node.js to run the parity cases. Concord parcel-dependent tests run when its downloaded layer exists; tests that do not need geometry still validate its committed models.

For frontend changes, check desktop/mobile layouts, keyboard access, search, overlap selection, calculator updates, citations, and deployment under a repository path such as /tax-map/concord/. Keep both formula implementations aligned and add parity cases for semantic changes.

Publish with GitHub Pages

This repository's Pages workflow installs taxmap, downloads Concord parcels, validates its model, builds its map, and combines it with the landing page and documentation. Pushes to main or manual workflow dispatch deploy the result.

For a standalone city project repository, copy the workflow template into .github/workflows/pages.yml. It assumes taxmap.yaml is at the repository root and a configured parcel layer is named parcels. Adjust paths or download steps if your project differs.

Guided apps: obtain separate deployment permission and publish only the exact approved export returned by app_preview, preserving its generated coverage page and disclaimer. Never publish the entire .taxmap cache. The template performs a low-level rebuild; it does not enforce guided approval or add the guided coverage page. Adapt deployment to the reviewed export or provide equivalent approval, reconciliation and coverage checks.

  1. Commit project configuration, approved sources, models, and required GIS definitions. Avoid committing large parcel downloads or generated caches.
  2. Check that the GitHub plan and repository visibility support Pages.
  3. Choose GitHub Actions in repository Settings > Pages.
  4. Run the workflow and inspect validation/build warnings and deployment status.
  5. Verify the actual public URL, a parcel deep link, calculator, and source links.

Keep links relative for repository-prefix hosting. Failed downloads or validation must stop deployment, rather than publishing an incomplete replacement. A manual rebuild does not automatically refresh adopted reports or review annual model changes.

Troubleshooting

  • No project open: pass --project or call project_open; confirm the folder contains taxmap.yaml.
  • Unmatched roll APNs: inspect normalization and coverage; check retired parcels and duplicates rather than discarding records silently.
  • Calculator cannot prefill: verify source fields and publication allow-list; read build warnings. Missing data is not zero unless the documented method says so.
  • Unreadable PDF: inspect rendered pages or obtain a better source. Text extraction failure does not prove a fact is absent.
  • Blank map: serve over HTTP and check data requests, paths, and console errors.
  • Pages unavailable: check permissions, repository visibility/plan, Pages source, and Actions logs.

See the repository for CLI help, issue reporting, and the latest schemas.
